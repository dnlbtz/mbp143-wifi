# Board file template for the BCM43602 in the MacBookPro14,3.
#
# mbp143-wifi-setup writes the board file from this at install. A line
# "name=@srom" gets that variable's value from the machine's own Wi-Fi chip:
# its SROM, where the factory stored the board's type and flags and the
# calibration of each chip. Every other line is written as it stands:
#
# - macaddr: Broadcom's default; NetworkManager gives each machine its own
#   address instead (macbookWifiStableMac.conf).
# - ccode, regrev: the firmware's table for Germany, revision 2, which allows
#   80 MHz channels on 5 GHz. Elsewhere brcmfmac switches to the local table.
# - boardflags3: the firmware does not start with the chip's own value.
# - pa2ga0, pa2ga1, maxp2ga0, maxp2ga1: the 2.4 GHz calibration of chains 0
#   and 1 from the MacBookPro13,3's board file. With the chip's own values
#   this firmware does not connect on 2.4 GHz.
# - aga0, aga1, agbg0, agbg1: antenna gains from the same file; the chip's
#   own lower the 2.4 GHz transmit power by 3.5 dB.
# - rssicorrnorm_c0, rssicorrnorm_c1: the chip's own make the reported
#   signal 8 to 12 dB wrong with this firmware.
# - vendid, devid, muxenab, otpimagesize, nocrc, AvVmid_c*, rssicorrnorm5g_c*
#   and the btc* lines (Bluetooth coexistence) are not stored on the chip;
#   they come from the MacBookPro13,3's board file.
